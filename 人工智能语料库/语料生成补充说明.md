# 语料生成补充说明

## 当前语料不足问题分析

根据实际测试发现，当前训练的模型在生成**查询栏+列表**类型的页面时存在严重问题：

### 主要问题表现
1. **输出中断** - 模型在复杂结构中"迷失"，不知道如何继续
2. **怪异内容** - 模型在不确定时产生随机内容  
3. **不予响应** - 模型对不熟悉的模式缺乏信心
4. **70%的错误率** - 表明模型对查询栏+列表模式的理解极不稳定

### 根本原因
- **表单布局语料充足** → 模型表现稳定
- **查询栏+列表语料不足** → 模型缺乏足够的训练样本

## 急需补充的语料类型

### 1. 查询栏+列表基础结构

**核心组件组合**：
- `CommonInquery` (查询栏) + `MithrilAntdTable` (数据表格)
- 这是企业管理系统中最常见的页面类型

**标准结构**：
```json
{
  "nodeid": "page_root",
  "name": "div", 
  "label": "页面根容器",
  "props": {"classes": "page-class"},
  "nodetype": "layout",
  "componentType": "div",
  "containerType": ["pageRoot"],
  "isTached": true,
  "children": [
    {
      "nodeid": "search_section",
      "name": "CommonInquery",
      "label": "通用查询栏组件",
      "props": {},
      "nodetype": "layout", 
      "componentType": "CommonInquery",
      "containerType": ["gridItem", "div", "MainCard", "pageRoot"],
      "isTached": true,
      "children": [
        // 查询条件组件
      ]
    },
    {
      "nodeid": "table_section", 
      "name": "MithrilAntdTable",
      "label": "数据表格",
      "props": {
        "columns": [
          // 表格列定义
        ]
      },
      "nodetype": "component",
      "componentType": "nomoComponent", 
      "containerType": ["gridItem", "div", "MainCard", "pageRoot"],
      "isTached": true
    }
  ]
}
```

### 2. 查询栏组件规范

**CommonInquery 可接受的子组件**：
- `MithrilInput` - 普通文本输入框
- `MithrilSelect` - 单选或多选下拉框
- `AntdDateRangePacker` - 时间范围选择器
- `NumberRangeInput` - 数字范围输入框
- `CustomNumberInput` - 数字输入框
- `MithrilAutocomplete` - 自动完成输入框
- `MithrilTextArea` - 多行文本输入框
- `SingleDatePicker` - 单日期选择器

**查询项配置规范**：
```json
{
  "commonInqueryItemProps": {
	//name字段必须有
    "name": "fieldName",
	//defaultValue字段必须有
    "defaultValue": "",
    "label": "字段标签",
    "selectItems": [
      {"label": "选项1", "value": "value1"},
      {"label": "选项2", "value": "value2"}
    ],
    "dateFormat": "YYYY-MM-DD"
  }
}
```

### 3. 表格组件规范

**MithrilAntdTable 列定义**：
```json
{
  "props": {
    "columns": [
      {
        "dataIndex": "fieldName",
        "title": "列标题", 
        "align": "left|center|right"
      }
    ],
    "sticky": {"offsetHeader": 0},
    "scroll": {"x": 1500}
  }
}
```

## 重点补充的语料场景

### 1. 企业管理类
- **订单管理** - 订单号、客户名称、订单状态、下单时间查询
- **库存管理** - 商品名称、分类、库存状态、入库时间查询
- **财务管理** - 交易类型、账户、金额范围、交易时间查询
- **客户管理** - 客户姓名、类型、注册时间、等级查询
- **员工管理** - 员工姓名、部门、职位、入职时间查询

### 2. 金融业务类
- **股金账户管理** - 社员名称、股金账号、业务时间查询
- **交易记录** - 交易流水号、交易类型、金额范围查询
- **账户明细** - 账户状态、业务时间、办理人查询

### 3. 资产管理类
- **土地资产登记** - 资产名称、承包人、登记时间查询
- **房屋资产管理** - 建筑物名称、使用方、租赁期限查询
- **流转信息** - 坐落地址、租金、承包期限查询

### 4. 系统管理类
- **参数管理** - 参数名称、键名、系统内置查询
- **操作日志** - 操作地址、系统模块、操作人员查询
- **访客管理** - 访客名称、公司名称、手机号码查询
- **资讯管理** - 标题、创建者、创建时间查询

## 语料生成质量要求

### 1. 结构完整性
- 确保 JSON 格式正确，无语法错误
- 所有必需字段完整（nodeid, name, label, props, nodetype 等）
- 容器类型匹配正确

### 2. 业务合理性
- 查询条件与表格字段逻辑对应
- 字段名称有业务意义
- 下拉选项符合实际场景

### 3. 组件规范
- CommonInquery 只包含允许的子组件类型
- 查询项配置格式正确
- 表格列定义合理

### 4. 多样性要求
- 不同业务场景的查询条件组合
- 不同数量的查询字段（1-6个）
- 不同数量的表格列（4-12个）
- 包含操作按钮的复杂布局

## 生成建议

### 1. 优先补充类型
- **简单查询栏** - 2-3个查询条件
- **复杂查询栏** - 4-6个查询条件  
- **带操作按钮** - 包含新增、编辑、删除等按钮
- **纯列表页** - 无查询条件，只有表格

### 2. 质量保证
- 每个语料都要测试 JSON 格式正确性
- 确保在低代码编辑器中可以正常加载
- 避免重复的语料内容
- 不存在 MithrilDateRange 等其他时间范围 组件，时间范围有且只有 AntdDateRangePacker
- AntdDateRangePacker 必须在commonInqueryItemProps填写 "name":["start","end"],"defaultValue":["",""]
- commonInqueryItemProps中"name":["start","end"],"defaultValue":["",""],这两个字段对于AntdDateRangePacker非常重要

### 3. 数量目标
- 至少补充 **200-300** 条高质量的查询栏+列表语料
- 覆盖所有主要业务场景
- 包含各种复杂度的布局结构
